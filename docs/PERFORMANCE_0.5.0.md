# 0.5.0 真机滑动验收

2026-10-30，vivo V2520A / Snapdragon 8 Elite / Adreno 830 / Android API 37。
本轮 0.5.0 非调试性能版实际运行于 **120 Hz**，20 次词本滑动记录到 1,693 帧，
现代 `gfxinfo` jank 为 0；帧耗时 P99 桶值由旧版的 32 ms 降为 6 ms。
这说明本轮渲染流畅性改善，不等于测得零触摸延迟，也不是所有场景永不卡顿的保证。

## 方法

- 同一手机、1440 × 3168 分辨率、640 dpi、字体缩放 1.0。
- 页面：练习 → 记忆工坊 → IELTS 总词本；初始列表顶部、空搜索、全部筛选。
- `work/Capture-WordbookScroll.ps1` 执行 20 次交替滑动：
  `(720,2400) → (720,900)` 与反向，单次 250 ms，间隔 350 ms，最后静置 1,200 ms。
- 测量前重置本 App 的 `gfxinfo` 统计；没有播放语音、调用 AI 或提交学习记录。
- 旧版采样：2026-10-30 00:57:34–00:57:51 +08:00。
- 新版采样：2026-10-30 11:46:59–11:47:14 +08:00。

## 结果

耗时来自 `dumpsys gfxinfo` 直方图分位桶，不是高精度触摸到屏幕响应时延。

| 指标 | 0.4.3 基线 | 0.5.0 性能版 |
| --- | ---: | ---: |
| 安装包模式 | debuggable | 非 debuggable，R8 |
| 实际刷新率 | 60 Hz | 120 Hz |
| 显示周期 | 16,666,666 ns | 8,333,333 ns |
| 渲染帧数 | 873 | 1,693 |
| 现代 jank | 21（2.41%） | 0（0.00%） |
| 帧耗时 P50 / P90 / P95 / P99 | 5 / 12 / 15 / 32 ms | 5 / 5 / 5 / 6 ms |
| GPU P50 / P90 / P95 / P99 | 2 / 2 / 2 / 3 ms | 2 / 3 / 3 / 3 ms |
| Slow UI thread 计数 | 21 | 0 |
| Frame deadline missed 计数 | 21 | 0 |
| Legacy jank | 156（17.87%） | 1（0.06%） |
| High input latency 原始计数 | 303 | 1,056 |

新版前后两次显示快照均为 active mode 1、render refresh 120.00001 Hz；
SurfaceFlinger 显示周期为 8,333,333 ns，保留的 120 条 framestats 的 FrameInterval
也全部约为 120 Hz。旧版对应 active mode 4 / 60 Hz，因此不是仅设置了一个无效的开关。

`High input latency` 是系统诊断计数，并未在本轮下降。现代 jank 为 0 不能覆盖这个事实，
也不能据此声称所有输入响应均已解决。该计数不是输入延迟的毫秒测量；刷新率、统计帧数
和厂商系统实现均有差异。如需验证真实手指“跟手”程度，应另做输入事件/呈现时间追踪
或高速摄影，而不是把帧耗时或此计数直接当成端到端触摸时延。

## 适用边界

这是一轮相同滑动序列的整版体验对比，不是单一优化的严格 A/B：新版同时改变了 UI、
文字/卡片布局、列表数据处理、构建优化及刷新率策略；基线为调试版，新版为性能版。
两次测试也不是同时进行，未控制全部温度、电量、系统负载变量，不能把改善全部归因于某一处代码。
120 Hz 的帧预算约 8.33 ms，60 Hz 约 16.67 ms，jank 百分比不能脱离刷新率比较。
未在本轮覆盖边滚动边长文 AI、持续高温、极端内存压力或其他手机。
